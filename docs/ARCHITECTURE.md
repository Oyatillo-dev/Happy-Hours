# Архитектура

```
 Покупатель (Expo, iOS/Android)        Партнёр и админ (React PWA)
              │                                   │
              └──────────────► API (Fastify) ◄────┘
                                │      │
                      PostgreSQL ◄     ├──► эквайер (ELQR / карты) ── вебхуки ──┐
                                       ├──► SMS-шлюз                           │
                                       └──► Expo Push                          │
                                ▲                                              │
                                └──────────────────────────────────────────────┘
```

Один процесс API обслуживает всех клиентов и раз в минуту выполняет фоновые задачи. Все задачи идемпотентны, поэтому можно запускать несколько экземпляров.

## Ключевые решения

**Время.** В Бишкеке UTC+6 без перехода на летнее время. Моменты хранятся в UTC, а дата бокса — местной строкой `YYYY-MM-DD`. Так лента «на сегодня» и недельные выплаты не зависят от часового пояса сервера. Код — в `apps/api/src/lib/time.ts`.

**Без двойных продаж (NFR-03).** Остаток списывается одним SQL-запросом `UPDATE … SET sold = sold + n WHERE sold + n <= quantity`. Если строка не обновилась, бокс распродан. Тест запускает четыре параллельных заказа на два бокса.

**Переходы статусов.** Каждое изменение статуса заказа — это условный `updateMany` из ожидаемого статуса. Если фоновая задача и пользователь меняют заказ одновременно, выигрывает только один, второй получает понятную ошибку.

**Платежи.** Интерфейс `PaymentProvider` (создать платёж, вернуть деньги, проверить подпись вебхука). Тестовый провайдер ведёт себя как настоящий: показывает страницу банка и отправляет подписанный вебхук. Для продакшена нужен адаптер банка с тем же интерфейсом.

**Деньги партнёру.** Комиссия считается при создании заказа: процент партнёра или 0 в промопериод. Выплата за неделю = оплаченные боксы (выданные и незабранные) − возвраты по жалобам − комиссия с оставшейся суммы.

**Сотрудники точек.** Кассир привязан к одной точке и видит только её заказы. Владелец видит всё.

**Уведомления.** Каждое уведомление сохраняется в базе — оно видно в приложении, даже если push не дошёл — и отправляется на все push-токены пользователя. Тексты — на языке пользователя (ru/ky).

## Модель данных

`User` → (`Partner` → `Location`, `BoxTemplate`, `Schedule`) → `BoxOffer` → `Order` → `Payment`, `Review`. Дополнительно: `Favorite`, `Notification`, `PushToken`, `Payout`, `AuditLog`, `OtpCode`, `RefreshToken`. Полная схема — в [`apps/api/prisma/schema.prisma`](../apps/api/prisma/schema.prisma).

## Отклонения от SRS

- Выплаты формируются **во вторник в 01:00**, а не в понедельник: так успевают закрыться 24-часовые окна жалоб на воскресные заказы.
- Приложение для сотрудников — это PWA кабинета партнёра (экран «Выдача» со сканером QR), а не отдельное нативное приложение. Работает на любом телефоне без установки из магазина.
- Функции с приоритетом Could (реферальная программа FR-B12, баннеры и рассылки FR-A07) в MVP не вошли.
