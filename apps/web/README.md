# Sakta — веб-кабинет

Веб-приложение для двух ролей:

- **Кабинет партнёра** (PARTNER_OWNER, PARTNER_STAFF) — заведения публикуют боксы с излишками еды и выдают заказы.
- **Панель администратора** (SUPPORT, ADMIN) — модерация партнёров, заказы и возвраты, жалобы, выплаты, пользователи, журнал действий.

Покупатель (BUYER), вошедший в веб, видит форму «Стать партнёром».

Стек: React 18 + TypeScript + Vite, react-router-dom v6, @tanstack/react-query v5, обычный CSS, html5-qrcode.
Интерфейс на русском и кыргызском (переключатель RU/KY, язык сохраняется в профиле через `PATCH /me`).

## Запуск

```bash
# из корня репозитория
npm install
cp apps/web/.env.example apps/web/.env   # при необходимости поправить адрес API
npm run dev:web                          # http://localhost:5173
```

API должен быть запущен (`npm run dev:api`, по умолчанию http://localhost:4000).

Сборка и проверка типов:

```bash
npm run typecheck -w apps/web
npm run build -w apps/web      # результат в apps/web/dist (статические файлы, SPA)
npm run preview -w apps/web    # http://localhost:4173
```

При раздаче `dist` через nginx и т.п. все неизвестные пути должны отдавать `index.html`.

## Вход

По номеру телефона и SMS-коду. В режиме разработки API возвращает код, и он показывается подсказкой «Код для теста: 1234».
Демо-номера: админ `+996700000001`, владельцы `+996700000002` / `03` / `04`, кассир `+996700000005`, покупатель `+996700000010`.
Токены хранятся в localStorage; access-токен автоматически обновляется через `POST /auth/refresh`.

## Экраны

Партнёр (`/p/...`):

| Экран | Требование | Кто видит |
| --- | --- | --- |
| Статус заявки (на проверке / отклонена / приостановлена, с причиной) | FR-P01 | владелец, сотрудник |
| Боксы на дату: публикация, изменение количества, отмена с причиной | FR-P04, P05, P06 | все |
| Выдача: скан QR камерой или ввод 6-значного кода (крупная клавиатура для телефона) | FR-P07 | все |
| Заказы за день (автообновление каждые 30 с) | FR-P08 | все |
| Отзывы и жалобы | — | все |
| Шаблоны боксов с фото | FR-P03 | владелец |
| Расписание по дням недели | FR-P04 | владелец |
| Точки | FR-P02 | владелец |
| Сотрудники (по телефону, с привязкой к точке) | FR-P02 | владелец |
| Статистика | FR-P09 | владелец |
| Выплаты | FR-P10 | владелец |
| Профиль заведения | — | владелец |

Форма «Стать партнёром» для покупателя — FR-P01. Уведомления (колокольчик) опрашиваются каждые 30 секунд; новый заказ обновляет списки и показывает всплывающее сообщение.

Администратор (`/a/...`):

| Экран | Требование |
| --- | --- |
| Дашборд: GMV, доход, заказы, доля продаж, no-show, повторные покупки, графики по дням | FR-A06 |
| Партнёры: фильтр по статусу, поиск, карточка, одобрение с комиссией и промо, отклонение / приостановка с причиной, возобновление | FR-A01 |
| Изменение комиссии и срока промо | FR-A02 |
| Заказы: поиск по номеру или телефону, карточка, ручной возврат | FR-A03 |
| Жалобы: одобрить с возвратом / отклонить с решением | FR-A04 |
| Выплаты по неделям: расчёт, CSV для банка, отметка о выплате | FR-A05 |
| Пользователи: поиск, смена роли | — |
| Журнал действий | FR-A08 |

Действия, доступные только ADMIN (модерация, комиссия, расчёт и отметка выплат, смена ролей), для SUPPORT скрыты.

## Устройство

- `src/api/` — типизированный клиент (`client.ts`: токены, refresh, ошибки `ApiError` с кодом), типы ответов и эндпоинты.
- `src/i18n/` — словари `ru.ts` и `ky.ts` (одни и те же ключи; TypeScript не соберёт проект, если в `ky.ts` нет ключа). Ошибки API переводятся по коду: `err.<code>`.
- `src/lib/format.ts` — деньги («1 250 сом»), время в часовом поясе Бишкека (UTC+6), локальные даты.
- `src/lib/validation.ts` — те же правила, что в API: цена ≥ 100 сом, стоимость ≥ 2× цены, окно выдачи 30–180 мин в часы работы точки, ИНН 14 цифр.
- PWA-lite: `public/manifest.webmanifest` и иконки, без service worker.
